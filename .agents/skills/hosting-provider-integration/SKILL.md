# Hosting and provider integration

Read the assigned package/change, [deployment contract](../../../specs/shared/deployment-and-retention.md), [AI/privacy contract](../../../specs/shared/ai-and-privacy.md), relevant [G04/G08 gates](../../../specs/decisions.md) and [consumer handoffs](../../../specs/integration-handoffs.md). Follow additional affected contracts and complete scenarios through the task reading map.

## Validate prerequisites

- Identify the foundation revision, selected database/runtime approach, exact owned files and authorised remote operations. Independent access/limit research can proceed while executable integration waits for its foundation prerequisite.
- Verify current hosting/database allowances and eligibility from official provider sources. Obtain authoritative course material for SoC/provider restrictions; absent evidence remains an explicit compliance uncertainty. Do not infer connectivity from a developer-laptop result.
- Record access method, model identifier, quotas, cost implications, data handling and relevant runtime constraints without copying credentials. Full PDF/parser policy and both end-user AI workflows remain outside a connectivity-only slice.

## Exercise bounded server-side behaviour

- Route shared dependency/configuration requests through their assigned writer. Implement provider checks in the server boundary with synthetic non-private input; do not add an anonymous proxy or diagnostic route exposing credentials, raw prompts or internal errors.
- Keep configuration and test data isolated from production private data. Use the selected design's explicit timeouts, bounded retries and concurrency/token limits. Preserve unavailable or unvalidated limits as open; do not adopt historical numeric proposals by accident.
- Check success and relevant timeout, unavailable-credential and rate-limit outcomes. Deterministic stubs support failure checks; actual intended-host SoC calls supply separate connectivity evidence. Report truthful failure rather than treating outage as missing event information.
- Verify authorised hosted HTTPS access, durable reads/writes across requests and, when assigned, redeployment persistence. Record which checks need a second device or hosting access and remain unrun. Clean up only assigned synthetic artifacts.

## Evidence and recovery

Return intended host/environment, tested revision, check method/commands, actual outcomes, verified limits/source references, non-secret configuration names and recovery instructions. Separate local, stub and hosted/live-provider results. A probe supports partial T14/T15 evidence; it cannot prove complete PDF assistance, FAQ correctness, retention erasure or the full online journey. Leave dependent unresolved gates visible. Provisioning/deployment/provider spend follows the human's assigned scope.
