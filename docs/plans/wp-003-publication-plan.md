## Delivered design

Event holds immutable UUID/owner, lifecycle state, operation version, working draft/version, owner-edit time, first-publication time and a current-publication pointer. Draft JSON contains only allowlisted structured public fields, not a PDF or separate duplicated prose document. EventPublication stores immutable approved fields and an empty form with server-generated form revision, digest and minimal actor/time metadata. EventApproval stores the exact saved preview bound to actor/event/draft versions. No private-note/proposal/profile input is accepted by the event request schema.

All service operations resolve authoritative sessions/roles. Transactions lock account, revalidate session, lock the owned event, enforce expected version/state and revalidate again before commit. This follows credential-change lock order; queued operations cannot bypass revocation/absolute expiry. Publication validation runs at preview and again at publish using database time. Approval hashing canonicalises JSON object keys recursively, preserving array order, so JSONB round trips cannot invalidate unchanged approvals. Saving, discarding or changing lifecycle invalidates approvals. Published replacements create a new immutable revision; private edits leave the live pointer unchanged. Database constraints bind the current pointer to the same event and prevent publication updates and previously-published event deletion through the service.

GET/POST /api/organiser/events lists/creates owned events. GET/POST /api/organiser/events/[id] reads or performs save/preview/publish/withdraw/cancel/delete/discard with exact allowlisted payloads. Mutations require configured same-origin POST. Event bodies have a512KiB streaming ceiling and5-second read timeout (engineering transport bounds, separate from product text bounds); errors are private/no-store and dependency diagnostics are generic. The internal currentPublication reader projects current published content for authenticated Students, but no Student route/UI is delivered. Future consumers must recheck current revision/state at their commit/delivery boundary, especially during chat or registration.

Dashboard shows saved draft content for never-published events and last-publication title/schedule/content for previously published events, combined case-insensitive title search and title/owner-edit/start sorts in either direction; missing schedules sort last and UUID breaks ties. Sorting/search operate in memory over owned events for this initial bounded application; large-collection pagination/query optimisation remains a future performance change. Separate publication/editor/preview modes require saving before preview, preserve input on failures and require explicit reload/review for stale work. Cancel Editing resets unsaved values only. Discard Saved Draft is available for previously published events and restores the latest publication into a new saved working draft/version; never-published work uses Delete Draft. Native browser confirmations distinguish withdrawal/cancellation/deletion/discard consequences. Final cancellation removes editors/actions and preserves owner access to retained publication.

## Accepted layout/rescheduling amendment — 21 October 2026

Keith approved the follow-up plan and implementation. Cards are whole semantic links; the existing list DTO adds hasSavedChanges and selects publication-based fields for previously published events. Query search/title/start sort uses those displayed fields; modified order remains owner-edit time. One relation include loads the current publication; missing referenced content fails closed. Fixed-field comparison ignores JSON key order and version-only changes.

The event route retains view state only in React: publication/editor/preview. Default is publication when a historical publication exists, otherwise editor. Published/withdrawn/cancelled headings and unavailable notices are distinct; only applicable bottom lifecycle/edit actions render. Edit resumes saved draft, Save stays in editor, Cancel Editing drops local changes and returns to the appropriate default. Explicit Preview hides other modes, resets approval and shows normal-flow footer actions; Edit saved draft clears preview/approval. Delete removes only never-published events; Discard restores saved fields from the last publication, invalidates previews and returns to default. Editor removal controls are retained for invalid/incomplete drafts. Refresh recreates no approval/mutation and returns to default.

The timing helper retains previousStart only to distinguish an unchanged published past start from a changed start. Changed starts must exceed current database time for both preview and publish; they need not exceed the previous publication's start. Existing first-publication/withdrawn-republication future and end-after-start rules remain. No schema/migration/endpoint/dependency change. Existing account/state/version/approval transactions remain unchanged. Full-card accessibility, mode transitions, stale/failure input preservation and changed-start timing require regression/browser checks and independent implementation review. No Student/registration behaviour or delivery authority is added.
