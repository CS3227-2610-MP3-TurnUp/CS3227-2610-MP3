# Integration handoffs and evidence

Read with the [implementation plan](implementation-plan.md) and the affected [package plans](implementation-plan.md#dependency-ordered-work-packages). B1/D12 responsibilities and planned checks are unchanged; this guide is not implementation evidence.

## Integration checkpoints and independent preparation

These checkpoints make the existing dependency handoffs concrete. They do not require both humans to be online simultaneously. Record the producing revision, affected contract/scenario IDs, actual agent findings/checks and remaining gates in the assigned change verification. Review completed implementations with an independent agent, including executable configuration and agent/workflow instructions; standalone specification audits require explicit assignment. Evidence/log-only updates do not restart review. After an authorised push, GitHub review is the final PR review. Human reviewer assignment, independence, approval, sign-off and merge readiness are outside agent assessment under the [review policy](../CONTRIBUTING.md#review-records). Integrate prerequisites and rerun affected checks before relying on integrated behaviour; neither a clean merge nor a test double establishes compatibility by itself.

The [CLI deployment route selected on 18 October 2026](../changes/CHG-K-002-wp-001-foundation-design/design.md#selected-cli-deployment-route) governs future build/deployment evidence under G08. Its automation, credential/environment and migration boundaries belong in that design. Handoffs distinguish the selected method from actual execution, account/team/token access, policy/course eligibility and remaining provider evidence; no workflow or hosted check has run in this documentation increment.

The [foundation stack and Neon development/production design selected on 18 October 2026](../changes/CHG-K-002-wp-001-foundation-design/design.md#selected-application-foundation) governs future runtime/data/migration handoffs. Carry locked versions and actual compatibility/isolation/recovery evidence, including any explicitly recorded fallback allowed by the design. Synthetic-only non-production resources remain separate from independent production resources; no production credentials or private data enter development-agent handoffs. Selection supplies no account/region/allowance or runtime result.

## Agent assignments and evidence

| Specialist | When used | Bounded output and handoff |
| --- | --- | --- |
| SDD Coordinator / Project Manager | Before work and at dependent handoffs | Assignment plan, single writers/reviewers, source/spec revision, requirement/scenario IDs, paths, dependencies and actual status/evidence. |
| Requirements Analyst | Before a new or changed behaviour | Reconciled affected specs, explicit open decisions and observable acceptance scenarios. Avoid rewriting unrelated role scope. |
| Repository Workflow Builder | After the file-level scope is assigned | Agreed repository/process artifacts. The setup definition is not blanket authority to implement application features; future implementation assignments identify the needed implementer and skills. |
| Independent Implementation Verifier | After an implementation run, including executable configuration and agent/workflow instructions; recheck material fixes | Read-only completed-change correctness/security/regression/acceptance review; concise findings/checks/revision/limitations in verification.md. Agent must not have authored the change. |
| Independent Specification Reviewer | Only for an explicitly assigned standalone audit | Substantive contradiction/privacy/traceability findings affecting implementation or operation; no automatic per-document audit, human-review assessment or evidence-only review cycle. |

Historical setup on 16 October 2026 activated all four specialists. The Builder and Analyst authored disjoint outputs; Coordinator received sequential ownership of this plan and setup tasks/evidence; the parent agent integrated their staged files. Historical findings and check results are recorded in [setup verification](../changes/CHG-K-000-sdd-repository-setup/verification.md).

For application work, each change records what was specified, implemented and actually verified. Keep deterministic tests, concurrent database checks, browser tests, hosted checks and controlled SoC evaluations distinct. Never mark a scenario passed from a document or placeholder alone.
