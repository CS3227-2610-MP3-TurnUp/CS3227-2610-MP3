## Conflict selection and description wording — 23 October 2026

For each conflicting field, display up to three supported alternatives as keyboard-operable choices with their source evidence. Until the owner selects a choice, retain the existing input. Selecting a valid choice fills only its corresponding original input and removes that field's alternative suggestions; selected-value evidence may remain below the input and is cleared by subsequent manual edits. Other fields and their findings remain unchanged. Selection invalidates prior preview approval and delayed extraction results, and never saves or publishes. Disable selection during event writes; stale or invalid alternatives cannot bypass existing field validation.

Date/time choice labels use Singapore time in a readable day/month/year and twelve-hour clock format, for example 14/11/2026, 09:00 PM (SGT). Apply the corresponding canonical UTC instant to the existing date/time input; display formatting must not change the stored instant or infer missing components.

Extraction prompts request purpose/description wording in second person or an impersonal descriptive style, such as You will experience or This activity includes, without first-person or third-person participant narration. Rephrasing must retain source-supported meaning and exact verbatim evidence. This limited wording refinement does not implement the deferred ORG07 drafting/FAQ workflow. If more than three supported competing values exist, request the three best-supported/most plausible alternatives; retain conflicting status until owner resolution, without presenting numerical confidence or an automatic winning value. The output contract limits each conflicting field to two or three distinct supported alternatives. Live model interpretation and adherence require separate evaluation.

## Extraction field semantics — 23 October 2026

Location/participation instructions identify the source-supported event venue or, for remote attendance, a participation platform/medium such as Zoom or YouTube, plus stated joining instructions. Hybrid attendance may include both. Do not invent venues, links or platforms, or treat an unspecified/TBD venue as a confirmed venue. Open to identifies the stated intended/eligible participants, preserving supported audience qualifications without inferring eligibility from the organiser, speakers or topic. Preparation identifies participant requirements before attending, such as prerequisite knowledge/qualifications, required advance tasks, equipment/materials or software setup; distinguish requirements from recommendations and exclude organiser-only logistics. Absence of support does not establish Anyone or No preparation required.

Conflicts compare incompatible information serving the same semantic purpose for the same event fact/context. Complementary details (venue plus room/address, hybrid attendance channels, separate session schedules, compatible audience groups or preparation conditions) can be combined with supporting evidence instead of being treated as alternatives. Source-supported incompatible alternatives for the same fact remain conflicting and follow the existing two-to-three-choice bound. The prompt guides semantic interpretation; exact quote validation alone cannot prove that interpretation.

## Targeted clarification and server resolution — accepted 23 October 2026

CHG-K-011 extends the extraction slice with fixed inline field-specific questions/reasons, evidence and an unresolved-issues summary. Missing or conflicting required fields retain existing values until addressed. Selecting a supported alternative resolves that field locally; entering or retaining a manual value requires Confirm this value. Valid explicit answers may rely on organiser knowledge and are labelled Organiser-confirmed without fabricated PDF evidence or a mandatory explanation. Changing a confirmed value reopens only that issue. Confirmation does not save or publish.

A successful accepted Generate records structured issues on the server before returning. Save Draft commits working public values and validated resolution intents atomically under authoritative event/preparation revisions; unresolved issues do not prevent incomplete draft saving. Refresh restores saved answers and outstanding issues, discarding unsaved confirmations. Cancel Editing restores saved values/resolutions but does not erase newly recorded issues. Removing/replacing the selected file never silently clears outstanding issues or their short evidence. A subsequent extraction preserves previously confirmed values, reopens review if new findings disagree/conflict, and does not treat missing source information alone as contradiction. Failed, invalid, partial or stale processing cannot silently erase earlier unresolved issues. Model confidence does not resolve an issue on the owner's behalf.

Preview and publication independently enforce required public field validity plus absence of unresolved critical issues on the server. Preparation/source changes invalidate previous preview approvals; stale tabs/extractions/saves cannot overwrite newer preparation or public values. Manual-only events keep their existing complete-manual-draft path. Final public-content generation remains ORG07 later work and must consume the same completion contract when implemented.

Retain only bounded structured issues/short evidence and confirmed values/attribution, never the PDF/full extracted text. These are owner-only private preparation and excluded from public snapshots and Student AI. Never-published draft deletion removes associated preparation; existing saved-draft restoration preserves known issues and reopens changed confirmations as needed. The first implementation is synthetic/non-production only; production private-preparation retention/cleanup G06 and intended-host/provider G04 remain separate activation prerequisites. This supersedes browser-only issue state for the CHG-K-011 local slice; broader ORG07/full-WP-005 evaluation remains incomplete.
