# Agent usage contract

Accepted plan, 18 October 2026. This development tool implements no TurnUp application behaviour.

Registry v1: state/registry.json holds version=1, machine_id (random UUID), owner (keith/darryl), codex_home (absolute local path), projects=[{project_id,name,timezone,roots:[absolute paths]}]. Shared project identifier/config at .codex/agent-usage.json. Defaults: ~/.turnup-agent-usage; ~/.codex; TurnUp timezone Asia/Singapore. Local registry/state never exported.

Ledger public API: Ledger(state); snapshot()->dict with projects, threads, responses, bindings, annotations, diagnostics, collections arrays. init registers projects through CLI; collector consumes registry. Ledger.bind(thread_id,change_id,wp=None,from_turn=None); Ledger.annotate(root_turn_id,phase,outcome,evidence). Each root task default binding is inherited; from-turn boundaries select the latest boundary at or before a response's root-turn start. Parent links resolve nested descendants; unknown parents remain visible.

Response normalized fields: provider,response_id,project_id,owner,thread_id,turn_id,root_turn_id,timestamp,model,effort,tier,input_tokens,cached_input_tokens,cache_write_input_tokens,output_tokens,reasoning_output_tokens,total_tokens. Missing metadata null. Key provider+response_id; incremental usage only. Threads: thread_id,parent_thread_id,project_id,owner,role,agent_path,started_at,ended_at,cli_version,source_revision. Bindings: thread_id,change_id,wp,from_turn; annotations: root_turn_id,phase,outcome,evidence. Diagnostics have safe codes/counts; no prompts/tool bodies/account IDs/local paths exported. Collections record success time. Report consumes this snapshot; may derive attribution/rollups with explicit missing states.

Functions: collector.collect(state,full=False)->summary; collector.process_events(state,{filename:event})->consumed/pending/rejected filenames; exchange.export_data(state,output)->summary and import_data(state,paths)->summary; report.generate(snapshot,output)->summary. Automation hook(state,event)->queues minimal allowlisted JSON, returns no controlling feedback; setup(state,platform_name=None,apply=False)->summary creates preview unless apply is explicit; uninstall symmetric. CLI global --state, setup --apply controls actual installation; collect --scheduled updates report and drains queue only on success. Installed launcher pins a runtime copy and absolute Python. Scheduler runs every five minutes and at login. Hooks record lifecycle only; all registered sessions are catch-up scanned. Existing hook definitions and data survive removal.

No silent inferred change ownership. Metadata edits conflicting at import fail atomically; identical imports no-op. Facts with conflicting response identity fail rather than overwrite. Local diagnostics expose issues but never raw source text. Missing/native unsupported usage is coverage, not zero. Rate-card version and Standard speed comparison assumption appear in reports. Unknown models unpriced; cache/reasoning subsets are not added again. API estimates cover model tokens only, not bills or subscription allowances. Report task wall time and agent duration are distinct. Export schema v1 allowlists every field and rejects unsupported versions/fields.

Official sources fetched 18 October 2026: https://learn.chatgpt.com/docs/hooks (events/input/trust/background limits); https://learn.chatgpt.com/docs/pricing (Standard credits); https://developers.openai.com/api/docs/models/gpt-6.1-sol and https://developers.openai.com/api/docs/models/gpt-6-luna (API Standard, cache-write and long-context rules). Local JSONL is an internal version-sensitive interface. No runtime network access required.

Lifecycle correction: native task start/completion and queued lifecycle events are immutable normalized observations, exported with stable identities. Snapshot overlays thread/turn timing; raw facts export without derived mutable bounds. Scheduled collection acknowledges only persisted events after report success; unknown/rejected events remain queued. Reports distinguish recorded root-turn elapsed time, response observation span and whole-thread lifecycle (which may include idle/resume gaps).
