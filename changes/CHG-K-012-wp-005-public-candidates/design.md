# Bounded implementation contract

POST /api/organiser/events/[id]/public-candidates accepts only expectedVersion and expectedPreparationRevision. Source public fields are read from the authoritative saved draft under existing account/event locking; caller-authored facts/model/schema are forbidden. Enforce resolved required issues and existing complete-public-draft validation (including schedule rules), and recheck identical source/state/revisions/session after inference. Generation does not save fields/preparation or create publication approval. Response returns the authoritative versions and validated page-local candidates, never private preparation.

Shared types/constants/FAQ text renderer live in src/features/proposal-assistance/public-candidates.ts. The public source is a fixed allowlist of EventFields (including existing intended-public Other); derive display-safe SGT date strings and capacity strings server-side for readable, verifiable references. References name an allowed public field and a short exact quote contained in that field's supplied representation. Description is a bounded editable rephrase with supporting references; exact reference existence is deterministic, semantic accuracy remains separately evaluated.

For FAQ factual safety, model entries provide a question and exact public-field source references; server derives the suggested answer from the validated quotes. Empty references mean an unanswered organiser question, not an invented answer. No independent free-form model answer is accepted. Bound at most6questions, question200Unicode characters, at most3references per entry and300characters per quote. Render answered entries as plain Q/A text for Other; enforce its4000-character and existing combined-field bounds without truncation. Description remains within4000characters and second-person/impersonal style. Preserve exact evidence punctuation; never strip source quotes. Model output cannot choose executable UI/schema, recipients, provider settings or tools.

UI displays editable description/Other candidate text with supporting references and separate unanswered-question controls. An organiser may supply an answer to an unanswered question and explicitly add it to the Other candidate; unanswered questions are not included in applied public text by default. Apply description/Other separately, with explicit replacement confirmation for different nonblank target text, validate current field bounds, update only that working field and invalidate preview. Save/Preview/Publish stay explicit. Candidates are lost on refresh, dismiss clears only candidates, and dirty/resolution-pending drafts cannot generate from stale saved values. Request/editor/event/preparation tokens and busy guards prevent delayed overwrite or stale application.

Reuse the existing synthetic-only availability/transport, one bounded call and shared per-owner/shared durable admission. Do not reset or raise provider limits. No new persistence schema or dependency is needed. Use an isolated clean-environment mirror for builds; never load private env during validation/build, stop user servers or call a provider for verification.
