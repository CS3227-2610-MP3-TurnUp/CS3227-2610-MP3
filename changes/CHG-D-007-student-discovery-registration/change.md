## Proposed data and producer handoff (not an applied migration)

Darryl requests one Registration keyed uniquely by Student UUID/event UUID, current active/cancelled state, monotonically increasing version/generation and immutable joined-publication reference. Each successful join/rejoin has a fresh generation and immutable Submission versions with captured publication/form identity, form wording/option IDs, explicitly confirmed nullable name/phone and typed answers, submission version/time. Registration current-submission pointer must reference its own generation; corrections append, never overwrite. Enforce Student/event uniqueness and composite relationships to prevent foreign event/form/submission pointers; profile edits never rewrite stored snapshots.

Idempotency records are unique by actor/event/operation/key, with canonical payload digest and minimal committed own-result reference; old retries cannot execute after cancel/rejoin or cancel a newer generation. Reject changed payload for the same key. Exact replay returns the prior operation result with its generation, not false current status. Expiry must not silently recycle a key: reject expired/tombstoned replay until coordinated retention defines removal. No raw answers/profile in operational metadata.

Common lock order: account then session, event FOR UPDATE, registration row, scoped idempotency row. Join absent-row checks remain under event lock; final wall clock/state/publication/form/capacity/session/version checks and seat/submission/result commit are atomic. Keith's publish must take the same event lock and reject capacity below active registrations. Reject cancellation/correction of stale generations; rejoin uses current publication/form and fresh confirmation. Do not update event editedAt or publication revision because a Student joins/cancels/corrects.

Keith supplies exact schema/migration/producer revisions before dependent code; no migration identifier is invented. His roster receives current username/stable Student reference, joined time/state, captured form/publication/generation and latest versioned captured profile/answers with historical wording/options; never current global profile enrichment. Owner-only query remains his implementation. No shared agreement, SQL concurrency, owner roster integration or hosted readiness is claimed by this proposal.
